## Fixed

- **The update failed on Windows.** It replaced the application by renaming
  its folder, and Windows will not rename a folder while anything holds a file
  inside it — the browser's messaging host, a virus scanner, Explorer. Files
  are replaced one at a time now, and anything that cannot be written over is
  moved aside first, which Windows does allow.
- **Retrying a failed update broke the updater itself.** Each attempt reused
  one staging folder, so a second attempt deleted the files the first one was
  still running from. Every attempt now unpacks somewhere of its own.
- **Waiting for the application to close could kill it instead.** The check
  used a call that asks a question on Linux and terminates a process on
  Windows.

Because the new version is what performs the swap, updating **from 1.0.10 or
1.0.11 to this one uses the fixed code** — no manual install needed.
