## New

- **A download from the browser asks first.** Clicking a link opens a window
  with the address, the file name and the folder — plus **Start download**,
  **Download later** into a queue, and **Cancel**. A deferred download waits,
  paused, until the schedule that runs its queue starts it, and each queue in
  the menu says when that is. Switch it off in Settings → Integration.
- **Choosing a quality in the page opens the same window.** It appears the
  moment you click, while the stream is still being read, and its buttons come
  alive when there is something to start. A video and its audio are one file,
  so they move, start and cancel together.
- **A guide on the first run.** Five illustrated pages: the extension in Chrome
  and in Firefox, the panel on a video, and what happens when a download
  arrives. The extension folder is printed on it with a button to copy it, and
  the `?  Guide` button on the toolbar brings it back whenever you want it.

## Fixed

- **Starting one download by hand no longer waits for its queue.** With a queue
  paused by a schedule, pressing Resume on a single download put it straight
  back to *Queued* and said nothing. It starts now; the rest of the queue stays
  paused.
- **YouTube downloads show their size before they start.** The window said
  "size not published" while the list beside it showed the size. A stream with
  no separate audio track was missing its size in the list too.
- **A schedule set to "All queues" can choose its downloads.** It answered
  *"this schedule is not attached to a queue"* — the default setting was the one
  the feature refused.
- **The panel answers a click straight away on every route.** One path still
  held it on "Sending…" until the engine had finished, which on some sites is
  the better part of ten seconds.

The Log now times what a video download spends reading the page and asking the
streaming server, so a slow start can be explained instead of guessed at.
